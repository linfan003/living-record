# Living Record 协议

版本 0.1

本协议规定：Agent 在代表一个人做判断之前，可以依赖哪些个人记录。它不提供记忆数据库，不模仿这个人的声音，也不在这个人无法确认记录之后继续替他做决定。

`SKILL.md` 的文件格式以 [agentskills.io](https://agentskills.io) 为准。多个会话如何共用一个目录，见 [session-canon](https://github.com/linfan003/session-canon)。

## 1. 术语

| 词 | 含义 |
|----|------|
| 记录 | `records/` 里的一个 Markdown 文件。一件事一份。 |
| 范围 | 这条记录允许被用于哪一类问题。例如 `work`、`health`、`money`、`home`。 |
| 出处 | 这句话从哪来：本人说过、本人文件、推断。 |
| 复核日期 | 到了这一天，记录就不再自动有效。 |
| 判断 | Agent 给出的一个选择或建议。它必须列出所用记录的路径。 |

## 2. 八条规则

1. **先引用，再判断。** 回答里列出所用记录的相对路径。没有列出，就不能声称这个判断来自这个人的记录。
2. **一条记录六个字段。** 一句话、范围、出处、记下的日期、复核日期、状态。缺任何一个，这条记录不能用于判断。
3. **范围隔开。** 只读取和当前问题同一范围的记录。用户这一次明确说「健康的也看」时，才跨范围。
4. **本人说过的话优先。** 同一范围内，推断不能推翻本人说过或本人文件里的记录。推断单独存在时，回答里必须标出「推断」，并在照着做之前问一声。
5. **过期即停。** 状态不是「有效」，或今天已经晚于复核日期，这条记录不进入判断。可以把它列为「待复核」，并问它是否仍然成立。
6. **矛盾并置。** 同一范围里两条有效记录对不上时，两条都展示，写明各自的日期和出处。不平均，不挑选一个假装唯一。
7. **短而可拥有。** 路径相对记录目录，正斜杠。不写密钥、账号、证件号，不把聊天全量倒进记录。记录文件由这个人保存，不交给某一个 Agent 产品独占。
8. **人不在场就不延续。** 本协议只在这个人还能确认记录时使用。它不生成遗言，不模仿口吻，不把记录训练成一个会替他回答的人。

## 3. 目录

```
<记录根>/
├── AGENTS.md
└── records/<一件事>.md
```

## 4. 记录字段

```markdown
# <一句话>

- 范围：work
- 出处：本人说过
- 记下：YYYY-MM-DD
- 复核：YYYY-MM-DD
- 状态：有效

## 内容

能被原句引用的一段话。

## 停用

若被新记录替代，写新记录的相对路径。没有替代就留空。
```

出处只使用这三个词：`本人说过`、`本人文件`、`推断`。

状态只使用这三个词：`有效`、`待复核`、`已停用`。

本人文件要在内容里写相对路径，指到那份文件。推断要写它依据的是哪条记录或哪次观察；写不出依据，就不要建这条记录。

## 5. 判断时的顺序

1. 认出这个问题属于哪个范围。认不出就问，不猜测。
2. 只打开该范围里状态为「有效」、且复核日期仍在今天或之后的记录。
3. 若存在矛盾，先把矛盾告诉用户，暂停给出单一建议。
4. 给出建议时，每条依据附上记录路径、出处和复核日期。
5. 没有任何可用记录时，说「记录里没有这一条」，然后按普通问题回答，并标明这段没有个人记录支持。

## 6. 改记录

- 事实变了：新建一份记录，把旧记录的状态改成「已停用」，并在「停用」里指向新文件。不覆盖旧内容。
- 记错了：同样新建一份，旧记录改为「已停用」，内容保留。
- 复核日到了：把状态改成「待复核」。用户确认后，更新复核日期并改回「有效」。用户否定后，改为「已停用」。

## 7. 明确不做的事

- 不从聊天记录里自动抽取「全套个人数据」。
- 不把不同范围的记录拼成一份人格说明。
- 不在用户没确认时，把推断写成本人说过。
- 不提供死后继续对话的模式。
